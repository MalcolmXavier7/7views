# 7 Views: notes for whoever picks this up

Electron app for Windows. One frameless window covers a whole monitor (its work area, or all of it with "cover the taskbar"). Inside it, 2–6 web pages ("screens") sit wherever you put them, with a settings bar across the top. There is no docked side strip any more; the owner dropped it (Oct 2026).

`src/shell.html`/`shell.js` draws the settings bar, each screen's 26px bar and resize frame, the chips for screens that are off or floating, and the score ticker. The pages are `WebContentsView`s created in `src/main.js` and laid out by `computeLayout()`/`layoutPanes()`, so the bars and the pages always line up.

Name: 7 Views (formerly Side View, renamed Oct 24, 2026). main.js keeps using the old `%APPDATA%/Side View` settings folder when it exists so upgrades keep their settings. Internal names (`window.sideview`, `sv`, `SV_TEST`, `SV1-` layout codes) were kept on purpose: shared layout codes must keep working.

Decisions already made:
- Panes are embedded browser views, not real Chrome windows (simpler and more reliable).
- Every pane starts muted and re-mutes on navigation; unmuting one mutes the rest.
- Positions are fractions of the wall (`cfg.free`). Every monitor starts from the same layout; changes made on one monitor are kept for that monitor (`cfg.freeBy[displayId]`). Each of the 3 saved windows (workspaces) has its own `free`/`freeBy`.
- Presets (`presetLayout`): `side`, `center` (default: small screens on top, main big in the middle, a wide one at the bottom), `grid`. The last screen is the main one.
- Per-screen lock (`pane.locked`) and lock-all (`cfg.freeLocked`). Presets refuse to run while anything is locked. New or returning screens get a free spot (`ensurePlaced`/`placeNew`) instead of re-arranging everything.
- Settings bar: on/off only by the user (`cfg.topBar`, Ctrl+Alt+F, or the tab left at the top when it's off). No auto-hide.
- Control panel (`settings.html/js/css`, opened by the gear, the tray, a tray double-click or Ctrl+Alt+P): every setting, monitor and screen on one page. Main pushes `panelState()` (throttled to 100 ms, without the logins list) on every `sendState`/`refreshTray`; the page sends `panel:do` with an action name from `PANEL_ACTIONS`, which checks every argument. The page never overwrites a field that has focus.
- Discord server "7 Views .1107": `discord/server.json` (blueprint). The script that builds the server from it is kept out of the public repo. Private and invite-only. The legal line is deliberate and the owner agreed to it: legal sources only (AutoMod blocks known unlicensed stream sites), casting is for setups/the app/own content, Watch Party voice has screen sharing denied. Don't build features that pass stream links around.
- Layout codes (control panel > Community): `SV1-` + base64url of `{v:1, s:[[x,y,w,h] in thousandths]}`. Positions only, never URLs; `applyLayoutCode` rejects anything else and refuses while screens are locked. `cfg.discordInvite` must match `DISCORD_INVITE` before `shell.openExternal`.
- Favorites: `cfg.favorites` (max 16) with icons fetched once into data: URLs (the shell's CSP only allows `self`/`data:` images). The favorite button is two crossed bones (the owner's choice). Click a favorite: loads into the selected screen (`focusedId`); drag it onto a screen's bar; right-click for more.

- Presets: `row` (all side by side, equal: 2 halves, 3 thirds), `side`, `center`, `grid`. Changing the screen count or turning a screen on/off re-spreads everyone evenly in the current preset (`respreadEvenly`) unless something is locked; locking is how you keep a hand-made arrangement.
- Lock to part of the screen (`cfg.dockOn/dockEdge/dockSize`, Ctrl+Alt+K, top bar, control panel, tray): an AppBar band on any edge, 20–80% of the monitor; Windows shrinks the work area so other apps' maximized windows fill the rest. Off by default. The band is released when hidden, undocked, moving monitors and on every exit path. The settings bar drops less-used controls at narrow widths (shell.css media queries); everything dropped is in the control panel.

CRASHES, read this first: never make a koffi call that can make Windows send our window a message (SetWindowPos with a size change, SHAppBarMessage NEW/SETPOS/REMOVE) synchronously from JS. Electron answers WM_SIZE / AppBar notifications by running JS inside koffi's native call, and the process dies (access violation in koffi.node, jump to address 0, or 0xc0150010 "activation context"). Those calls live in appbar.js as `*Async` (koffi `.async`, worker thread); only `unregister()` at quit is synchronous. Docking steps also run through `inOrder()` so they never interleave. Don't use `EnumDisplayMonitors` (native callbacks); `monitors()` walks EnumDisplayDevices/EnumDisplaySettings and is cached (`monitorsNow`, cleared on display events). Crash evidence: Windows Event Viewer (Application, id 1000), `userData/Crashpad`, `userData/7views.log` (crashed pages/helpers, uncaught errors; crashed pages reload themselves).

Gotchas (found the hard way, on a 200% DPI laptop plus two other monitors):
- Never position the window with `win.setBounds` alone: Chromium can undo it. `coverScreen()` places it with `SetWindowPos` (`appbar.moveWindowAsync`, on a worker thread) in physical pixels and `placeUntilItSticks()` re-checks with `GetWindowRect`, because moving between monitors with different scaling makes Chromium resize the window (WM_DPICHANGED).
- Electron's display numbers are wrong for a second monitor with different scaling, so `appbar.monitors()` asks Windows (display devices + their current mode, no callbacks) and `physical()` matches them to Electron's displays by size.
- Nothing lays the pages out unless something calls `layoutPanes()`: the window is created at its final size, so no resize event comes. `showWall`, `coverScreen`'s done callback and `shell:ready` all call it.
- Drags: as soon as the pointer is over a page, the shell stops getting pointer events. So the shell only says "drag started" (`free:start`, `wall:drag`); main follows `screen.getCursorScreenPoint()` and asks Windows whether the button is still down (`appbar.mouseDown()`, `GetAsyncKeyState`). On release: pointer over another screen → swap; overlapping → glide back; resize never grows into a neighbour. The dragged page is raised by re-adding its view.
- Screens can't reach apps on this PC: `onBeforeRequest` cancels requests (http and ws) to 127.0.0.1/localhost unless the page itself is local or it's the screen's own top-level navigation (`resourceType === 'mainFrame'`, i.e. you typed or opened a localhost address). Discord's invite page scans `ws://127.0.0.1:6463-6472` for the Discord app, which then jumped in front of 7 Views a second after launch (it looked like a gray box in masked screenshots).
- A site that fails to load shows `error.html` ("Couldn't load ..."); the screen's reload button retries the site itself.
- `-webkit-app-region: drag` stops working once a `WebContentsView` is in a window, so the PiP window's bar is dragged in code too (`pip:drag`).
- Real acrylic doesn't show on this frameless `thickFrame:false` window (tried `backgroundMaterial` and `DwmSetWindowAttribute(38)`). "Glass" is CSS only.
- Fullscreen: the app window is `fullscreenable: false` and the permission handler allows only `fullscreen`, so a page's own fullscreen fills just its screen (`entry.fs`). Denying `fullscreen` makes `requestFullscreen()` hang forever. "Show only video" has `off`/`fit`/`fill` and injects into every frame (`framesInSubtree`), re-running every 2.5 s.
- Picture-in-picture moves a screen's view into its own frameless window owned by `win` (owned windows stay above the owner). PiP screens leave the layout and show as chips; switching windows or hiding the screen puts them back.
- Logins: `vault.js` stores Chrome CSV imports in `logins.bin` via `safeStorage`. Pages never get to name the site: `vault:lookup`/`vault:password` match on `e.senderFrame.url` and answer only a screen's top frame. We deliberately do NOT read Chrome's own password store.
- `config.json`: a BOM is stripped before parsing (it used to silently reset everything). A missing or unreadable file goes through the normal load path, so the other windows exist on a fresh install (switching to Window 2 used to crash there). Old strip settings (`width`, `side`, `mode`, ...) are dropped on load; more than 6 screens in an old config are cut to 6.
- `appbar.js` still has the AppBar calls; nothing registers any more, but `releaseSpace()` runs on exit in case an older version left space reserved.

Self-test: `SV_TEST=1 SV_TEST_OUT=out.json electron .` runs `src/selftest.js` in a hidden window with a throwaway profile (never touches real settings or a running 7 Views), drives every feature, times the hot paths and runs the A/B comparisons. 39 checks; keep it passing. `PERF` in main.js holds the speed switches the A/Bs picked: `frameMs: 8` (Windows timers round 16 ms up to ~31 ms, i.e. 33 fps; 8 gives ~64 fps at no CPU cost; 4 costs CPU for nothing), `panelThrottleMs: 100`, `favoritesEveryState: false` (icons only travel when favorites change: 1.9 KB per frame instead of 191 KB).

Pluto TV field-test fixes (Oct 23, 2026): glides photograph moving screens (`captureStills`, `gliding`, shell `.still` imgs) so video layers don't flash black; `stopTween()` must be used to cut a glide short (it restores hidden pages). Video modes are `off/fit/fill/bottom` (`bottom` = cover + object-position bottom). Zoom is remembered per site (`cfg.siteZoom`, `rememberZoom`); "all screens" zoom clears it. `resourceStats()` feeds the control panel's memory/CPU meter (per screen = all processes its frames use). Favorite names go through `cleanTitle`. Monitor sizes come from `physical()` (fixes 1922x1080). Self-test: 46 checks (run it with no 7 Views docked, or the grid-snap check can see an odd-width wall).

Verified on the owner's machine (Oct 2026): full-screen wall, monitor picker, bar drag (same monitor), screen drag/swap, presets, locks, favorites, settings bar on/off. Not yet verified: dragging the bar onto a different monitor, "fill" on a real video player.
